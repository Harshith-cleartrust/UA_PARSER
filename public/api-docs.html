API documentation

← Back to parser

Base URL is your deployed origin (e.g. https://your-host.example). All JSON APIs use Content-Type: application/json unless noted.

Client Hints in API calls: Only fields you send in the JSON clientHints object are used for /api/parse and /api/ai-analyze. Browser HTTP Sec-CH-UA-* headers are not merged automatically (use /api/ch-probe in the UI to copy them into the form).

Audit log

When AUDIT_LOG=1 (enabled in npm start / npm run start:https), each /api/parse and /api/ai-analyze call appends one JSON line to a date-based file: data/audit/YYYY-MM-DD.jsonl (gitignored). Check GET /api/health → auditLog for today’s file path. 

{"at":"2026-05-29T...","type":"parse","endpoint":"/api/parse","ip":"10.0.0.1","ok":true,"modelKey":"sma266b","durationMs":12,"userAgent":{"mode":"truncate","length":180,"value":"Mozilla/5.0 ..."}}

Env: AUDIT_LOG_PATH, AUDIT_LOG_UA_MODE=truncate|full|hash. Logs are not returned by the API — read the file on the server.

GET

/api/health

Server status, parser version, dataset size, and cache flags.

Response

{
  "ok": true,
  "parserVersion": "0.3.56",
  "indexedModels": 8253,
  "deviceDbVersion": "...",
  "gsmarenaAllowed": false,
  "modelParseCache": { "enabled": true, "entryCount": 9650, ... }
}
GET

/api/ch-probe

Echoes Sec-CH-UA-* headers the browser sent on this request (after Accept-CH). Used by the UI “Use this device” flow; same-origin only.

Response

{
  "clientHintsFromHeaders": {
    "secChUaModel": "\"SM-A266B\"",
    "secChUaMobile": "?1",
    "secChUaPlatform": "\"Android\""
  }
}
POST

/api/parse

Main detection endpoint. Returns browser, platform, and hardware properties in one response (from model_parse_cache.json when cache mode is on).

Request body

{
  "userAgent": "Mozilla/5.0 (Linux; Android 12; SM-A266B) ...",
  "clientHints": {
    "secChUaModel": "\"SM-A266B\"",
    "secChUaMobile": "?1",
    "secChUaPlatform": "\"Android\"",
    "secChUaPlatformVersion": "\"16.0.0\""
  }
}

clientHints is optional. Keys: secChUaModel, secChUaMobile, secChUaPlatform, secChUaPlatformVersion (aliases like Sec-CH-UA-Model are normalized).

Response (default)

Only meta and properties — no debug, gsmarena, or other fields.

{
  "meta": {
    "parserVersion": "0.3.56",
    "deviceSet": "SMARTPHONE_HARDWARE_FLAT",
    "deviceDbVersion": "1.2",
    "deviceDbLastUpdated": "2026-02-19",
    "indexedModels": 9428,
    "parseTimeMs": 4
  },
  "properties": {
    "BrowserName": "Chrome Mobile",
    "BrowserVendor": "Google",
    "HardwareModel": "SM-A266B",
    "PlatformName": "Android",
    "Operating System": "Android",
    "Android WebView": "No"
  }
}

Internal/debug fields: ?format=detailed (used by the web UI only).

POST

/api/ai-analyze

Risk analysis via Konsole AI. Runs local parser first, then merges AI score with parser signals (e.g. UA vs model Client Hint mismatch). Requires AI_ANALYZE_API_KEY on the server.

Request body

{
  "userAgent": "Mozilla/5.0 ...",
  "clientHints": { "secChUaModel": "\"SM-A266B\"", "secChUaPlatform": "\"Android\"" }
}

secChUaPlatformVersion is stripped for AI analysis (not used for risk scoring).

Response (summary)

{
  "ok": true,
  "riskLevel": "low",
  "riskScore": 3,
  "summary": "...",
  "reasons": ["..."],
  "recommendation": "...",
  "localDetection": { "properties": { ... }, "debug": { ... } }
}

501 if AI is not configured on the server.

Example: curl

curl -s -X POST https://YOUR_HOST/api/parse \
  -H "Content-Type: application/json" \
  -d '{"userAgent":"Mozilla/5.0 (Linux; Android 12; SM-A266B) AppleWebKit/537.36 Chrome/120 Mobile Safari/537.36"}'
